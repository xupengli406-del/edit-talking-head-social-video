# 字幕与可见动效

## 建立稳定版式

先看整段人物活动范围，给脸、字幕、图形和平台界面留位置。人物移动时不能只检查一帧。普通字幕和轻量图形优先放在原片空处。关键真实资料可按本用户已确认的偏好居中盖脸，或占据主画面并配真人小窗；与满屏口播穿插，避免无意义黑边。资料盖脸是明确的视觉切换，不代表所有文字都可随意压脸。

白色正文与少量暖黄强调可作为延续风格的起点。普通标题和字幕默认透明背景，配细描边/柔和阴影适应明暗变化；避免厚黑字壳和反复出现的实色条。需要突出步骤状态、按钮或真实界面时可有功能性填充。字幕的位置、字号和对齐方式保持稳定。

## 字幕排版

- 逐句校对产品名、专有词、数字、否定词和语气，不直接信任自动转写。
- 一屏优先一至两行，按语义和实际字形宽度断开，不按固定字数硬切。“被迫离职”“桌面 Agent”等关键短语不拆成难读的碎片；不留下孤单字或标点另占一行。
- 通过分段、合理重排或减少同屏内容解决拥挤，不能只把字越缩越小。字幕忠于发言；画面概括与额外说明使用不同位置/层级，不混为同一句原声。
- 开始时间贴合发声，结束时间给阅读留余地但不拖到下一句话；动效标题与字幕别重复争抢同一位置。原声快、字多时优先保读完，不加逐字蹦跳。
- 在约手机显示尺寸下检查全片的短句、最长句、两行句和切换边界；安全区以实际构图和平台界面为准，不只看导出画布边界。

## 什么才算“做了动效”

用户要的是播放中明显可感知、帮助理解的变化。仅有静态字卡、很轻的透明度变化、极短的小幅缩放或代码里的动画声明，不足以证明完成了增强。

把值得动的内容变成状态：

| 口播语义 | 可以采用的视觉变化 | 完成态要让观众看懂 |
| --- | --- | --- |
| 少一个能力/模块 | 相关符号从一组中脱离，留下清楚缺位 | 缺的是哪一项 |
| 操作很绕/步骤很多 | 路径逐步推进，当前步骤接力高亮 | 到哪一步、为何繁琐 |
| 已连接/没接通 | 线段断开、接通，状态随之变化 | 两端关系发生了什么 |
| 前后差别/两种选择 | 并列、替换或局部展开 | 比较的具体维度 |
| 强烈反问/核心短句 | 短标题有明确入场或一次强调后落定 | 原声正在强调的意思 |
| 证据或操作细节 | 局部放大、遮罩聚焦、圈出相关处 | 证据本身仍可读 |

这是方法库，不是每条都用的模板。图形不能捏造真实产品界面、数字或能力；必要时明确是示意。

每个重点记录：**成片时间窗 / 原声锚点 / 唯一焦点 / 初始状态 / 动作 / 完成态 / 阅读停留 / 是否配短音效**。先设计完成态再决定如何进入，避免最后只剩乱飞的元素。

## 节奏建议与禁区

- 同一时刻只有一个主要变化。人物、字幕、大字和图形不要同时摇摆、缩放或抢视线。
- 按语义选重点，不按固定秒数强塞动画。普通话密集时画面更稳，复杂图形变化时给阅读时间。
- 可从约 0.3–0.7 秒动作、完成后至少约 1 秒可读停留起步；复杂流程需要更久，短强调可更快，以实播观感为准。
- 对近距离手持原片，优先让图形发生变化，不继续放大脸。固定机位才视需要加少量推近、切换构图或抠像。
- 不持续漂浮、呼吸缩放、故障闪烁或抖字幕；不靠无意义的烟花、贴纸和音效堆“网感”。也不要把克制误解成整片没有视觉事件。
- 开头直接建立本期核心问题，不默认长片头、无关片花或强迫三秒换场。结尾自然收束或保留原声提问，不补与本期无关的引流话术。

## 如何验收

实际导出有代表性的 15–30 秒片段，至少覆盖一个重点动作从前态到后态。片段可以来自中后部，不必只截开头；所有放置媒体与总时间线要真正截到测试区间，不能只缩短根容器时长。

以 1×、手机大小看：能否立刻指出动作发生在哪、它解释了什么、完成态能否读完。再检查动作前、中、后的连续帧，避免跳到终态、首次可见就已经完成、导出后动画失效等问题。静态截图可证明排版，不能证明运动顺畅。自动布局检查通过后仍要看实际最长标题：浏览器可能把最后一两个字折到下一行，与普通字幕重叠，而元素外框仍没有越界。优先缩短标题或按语义重排，并实际检查末字、标点和完成态。

用户反馈“看不出动效”时，先核对他看的是否当前文件，再检查实际导出；加强具体动作或重新选择视觉表达，不能只改名称为“增强版”。用户反馈太乱时，减少并发焦点、无意义动作和音效，保留真正解释内容的变化。

## 真实资料、图标库与动效设计

完整口播默认读 [真实资料与动效设计](icon-motion-design.md)，主动判断哪些口播锚点需要真实截图、产品图或品牌标识，不等返修才补材料。先解决面积、视觉层级和状态变化，再选择库；保留固定版本与许可，把网页交互动画改为可定位时间线，并检查所有剪辑接缝。


## 参考片吸收：短句分层与画面回应（2026-09-24）

参考：[许哈哈，一旦用 AI 建立起体系](https://www.douyin.com/video/7677217004918887845)。已在独立 Chrome 实际播放并抽看；以下区分实际所见与本 Skill 的执行建议。没有完整听审参考音轨，不据此认定音效类型、精确缓动或每秒动画参数。

实际所见：开头短句以白色普通字搭配亮色关键词；约 00:06 插入一张真实旧内容截图，占据真人主画面；约 00:24 “团队的 leader”用明显更大的粗斜体白字，前置语句较小；约 02:57 “我一下子就懂了”只把“懂了”变色并加下划线。参考并非每句话都用同一种字号和强调色。

### 转成可执行的规则

- 字幕按语义分普通层和重读层：铺垫约基准字号的 0.75–0.9 倍，重点约 1.25–1.5 倍。不是所有句子都放大，先选判断、反差、动作或结论中的关键短语。
- 默认白字配用户惯用的一种强调色，允许重点仅加粗或轻微斜体。变色、放大、下划线择一至两项；普通字幕继续无实色底板。
- 短句随原声接力。前置语可以短暂保留，后半句替换为重点；不要按单字不停蹦跳。每个强调在实际重读词发声时发生，不能刚出现就已完成动作。
- 同一句已经作为大字展示时，不在底部再重复一整遍。字幕承接原声，额外说明明确区分，不能把解释伪装成原话。
- 画面响应语义：讲真实例子时给可读证据，讲具体要求时聚焦该句，讲回到本人时退出资料恢复真人。优先让截图、圈线和关键词运动，不对近景人脸连续推拉。
- 模仿表现方法，保留自己的字体、色彩与真实素材；不挪用参考作者的案例，不把抽帧观察说成完整视听审片。

### “言出法随”演示的额外要求

先从原声词级时间确定动作锚点，再安排状态：说“放大”时从小到大，说“圈一下”时线条实际画出，说“回到我”时资料退场恢复真人。配合一次轻音效即可。所有后期效果明确为录制后对齐添加，不暗示实时自动操控。对话只能用真实截图或清楚标注的原文节选排版，不伪造聊天界面和完成记录。

渲染前检查 GSAP 等时间线的初始状态：后出现的元素必须在所属片段开始时保持隐藏，等待自己对应的口播锚点；禁止由于未来 fromTo 未初始化而提前出现。
