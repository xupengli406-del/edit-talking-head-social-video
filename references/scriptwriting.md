# 从口喷到可录口播稿

用于真人录制之前的口喷整理、写稿和改稿，与本技能的剪辑阶段共用观点、事实与视觉规范。写稿的交付是用户能自然念出来的一版完整正文，不是选题卡、提纲、通稿或分镜脚本。用户只要思路或选题评估时按其范围交付，不擅自扩大成全文。

## 1. 先听懂用户要表达什么

用户的口喷是立场、经历和语言风格的主要依据。音频有可用转写能力时先转写；不要假称听过无法感知的录音。提取：在聊谁/什么、用户想给出的结论或疑问、亲身经历、让他有情绪的细节、支持结论的理由、记不清的事实。整理重复和跳跃，保留有个性的口语、例子与态度。

区分“我已经买了”“我想买”“我觉得未来会发生”及“官方宣称”。不能为了有力度把意愿写成经历、设想写成现实、个人态度改成所有人适用的推荐。明显矛盾先核对上下文；关键的个人经历或立场无法确定时问一个具体问题，不用猜测填满。

用户明确的对象、结论、选定文案和时长优先。已有足够内容时直接出稿，不例行询问平台、风格、受众等已能推断的信息。没给时长时以讲清一条主线为先，说明预计时长而不是默认凑三分钟。

## 2. 受众和观看动机先于修辞

先简记：主要给谁看；为什么会关心；看完得到什么判断、方法或对创作者的理解；哪些原始材料能兑现。个人观点允许结论先行，让观众为了听理由继续看，不能把所有稿都改成教程、问句或强行省钱省时。

本用户强调内容的利他性。写正文前必须能用一句具体的话说明：“看完这条，哪类观众在什么场景下，会多一个什么方法、判断依据、避坑条件或有意义的共鸣？”并指向正文的兑现段落。仅“更了解我”或“知道我想买”不自动算收益；把个人选择背后的理由与适用条件讲给观众，让他们能对照自己的情况。答案空泛时先收窄主线、补一个真实例子或必要事实，再出稿，不靠更强语气和更密动效补救。资料不足不得编造体验、操作步骤或效果。

“我的结论”与“观众收获”可以同时成立：开头讲我为什么作这个选择，正文交付观众可借鉴的判断条件。首句与首帧可用本人态度吸引注意，随后尽快提供具体依据；没有实际依据就缩小承诺。检查时问“去掉作者名字，这段对目标观众仍有什么价值”，作为编辑提示，不强制删除人设、故事或真实情绪，也不回改用户已经指定的标题。

用户要求评估选题、主线不成立或目标受众不清时，使用可用的 `ai-content-opportunity`，沿用已经做过的判断；明确主题的普通改稿不重复全套打分。选题证据不足时缩小承诺或指出最小补证动作，不靠夸张标题掩盖。使用者路径关注实际场景与选择条件，认知路径需要理由、案例与边界；不把“以后一定满街都是”独自当完整论证。

从口喷里选择一个最有个人依据的中心理由，其他素材服务它。需要舍弃跑题段落时保留核心立场，不偷偷把产品话题改成创作者工作流。

完整新稿按[内容目标与数据复盘](performance-review.md)选主要目标，并标出“第一处真正给观众东西”的段落。实用类优先考虑真实结果或具体问题开场，再给方法；概念类优先选择案例入口。首个收获不能只是“后面教你”，不靠反复承诺拖延。按任务所需决定长度，不能根据一次数据将所有稿压成同一时长。

## 3. 录制前核实事实

对品牌、型号、价格、预订规则、功能、版本、上市时间、尺寸/重量和引用说法，查与本期时间及版本对应的一手来源。用户说记不清时主动补查；旧稿或旧会话不等于当前事实。找不到官方资料时说明次级来源及不确定性，不把猜测写成确定口播。

在现有制作说明或稿后简记需要引用的关键说法、来源链接、查阅日期与限制，并标记可用于后期的真实截图/产品图/演示页面。只是找到页面不能声称已经拿到可用高清素材；此阶段不用提前下载整套资料、生成动效或做封面。

有证据才加入具体数字和性能结论；官方演示写成“发布会展示/官方介绍”，亲测写成亲测，设想保留条件。不能替用户编造购买、试用、收入、效果、失败经历或对比实验。重要未知会影响结论时先补证；仍不可查则删去该断言、明确限定或交待证草稿，不能把含待填事实的稿称为可直接录制终稿。

## 4. 写成本人能说出口的话

默认交一版推荐稿，沿用户的措辞和情绪组织，不先抛十个标题让用户重做选择。常见主线是“明确态度/具体问题 → 最有说服力的理由或场景 → 必要事实与条件 → 本人的下一步”，按内容调整，不固定三段式。

- 句子一口气能说完，长解释拆成连续短句；避免一串定语、名词和括号。
- 保留有作用的“我觉得”“你想想”等口语，不保留找词失败和重复绕圈，也不每句添加“兄弟们”“说实话”。
- 先讲具体场景，再解释它为什么有意义。品牌、术语只解释到听懂当前论点的程度，不用术语堆出专业感。
- 让事实支撑态度，但不写成逐项念参数。不同人群的用途不要无差别罗列，突出与用户自己最有关的一两个场景。
- 少用“赋能、重塑、颠覆、重新定义、未来已来”等宣传腔；不编造“省90%”“最强”“闭眼买”的承诺。
- 结尾与开头一致，可以是下一步、适用条件或一个具体讨论点；不强加关注点赞、不许诺用户没答应的评测或更新频率。

正文只放要念的话，以自然段排版；不要混进网址、素材文件名、时间码或“镜头推进”。有确需朗读的英文、数字或同音词，录制提示另给正确念法。用户已指定标题原文就准确保留，不擅自换同义词。

## 5. 写稿时设计首帧与开头两秒

读取[开头两秒与留存](opening-and-retention.md)，在成稿前确定最初一句、首帧上能看见的对象/主张、随后第一条理由。没有原片时可直接写自然的新句，但明确这是待用户录制的稿，不伪装成已有原声。

首句话尽早给具体态度、问题或结果，删掉没有信息的“大家好今天跟大家聊一下”。不是所有稿都要惊讶、反转或强硬购买结论；按本人立场选择。两秒内让人抓住观看入口，不强迫两秒说完长标题。视觉标题可先说明对象，嘴里说本人结论，两者互补、不堆两套长句。接下来开始兑现，不用“你绝对想不到”反复拖延。

稿后最多给少量关键画面提示，例如“这句出官方价格截图”“当前功能与未来设想切开”“首帧真人加短标题”。不逐句硬配动效，不要求用户为了动画表演陌生动作。需要补拍实物、屏幕结果或其他不可替代素材时，录制前具体提醒。

## 6. 成稿检查、确认和接片

交稿前沿稿做口语检查：指代是否清楚；主张与理由是否相接；转折是否自然；同一信息是否重复；首句是否有观看动机；用户态度是否保留；事实及体验状态是否准确；结尾能否兑现。可实际朗读时据此改拗口处；没有音频感知时只能称文字口语检查，不能声称用户读起来一定流畅。

时长优先参考该用户已有原片的实际语速和停顿；没有数据时给粗略范围并标为估计，考虑数字、英文与停顿，不把字符数换算成精确秒数。超过明确目标时删冗余、减少次要分支，不靠要求用户超速念完。写稿阶段不自动调用付费TTS或克隆用户声音做试读。

默认交付顺序：一句话说明本稿的主线 → 完整可复制口播稿 → 稿外的必要事实来源、粗略时长、首帧/录制提示。没有特殊问题不附长篇自评。平台支持写作块时将完整稿放入可复制写作块，说明留在外面。

用户说“可以”“就这个”“我去录”即视为该稿确认，无需再次确认同一稿。按用户流程，此阶段交稿后由用户决定并录制；未收到视频不继续渲染，不开自动化等人。用户随后直接发视频并要求处理，按后期授权继续，不能以缺少形式化确认卡住工作。

已有项目时在当前说明里维护“草稿/已确认待录制/已收到原片/后期中/待审阅”等实际状态；没有项目时对话交付即可。只维护一份当前稿与必要来源，不为每次改字保留一排旧版本；用户仍在比较的候选按既有整理规则保留。

收到视频后，以实际说话校对字幕，比较是否遗漏关键条件或出现新的事实问题。允许自然脱稿，不机械追求逐字一致；必要时用原声可成立的剪辑或准确资料标注处理，实质性新错误才提出局部补录。沿用已确认的受众、立场和开头意图，实际字幕与动效时点必须重新按录制音轨对齐。
