# 验收与整理

## 检查实际成片

验证层次分开记录；用户选定可以作为版本选择依据，但不能自动补出未做过的技术检查或主观试听。

| 检查层次 | 看什么 | 不能冒充什么 |
| --- | --- | --- |
| 文件与依赖 | 真正输出文件的比例、尺寸、时长、帧率、声道、音视频轨；可完整解码；本地素材/字体/软链接可用 | 不代表好看、顺口或内容正确 |
| 时间与内容 | 源片映射、删段后语义、字幕错词、变速后的口型及图形锚点；开头、中段、后段均核对 | 少量抽点不等于整片听过 |
| 画面 | 手机尺度的排版；最长字幕；脸的活动范围；每个重点动作前中后；所有实际封面比例 | 单帧截图不能证明运动流畅 |
| 声音与节奏 | 在有实际音频感知能力时，完整 1× 试听，检查字头字尾、切口、喘不过气、音色、音效盖话及前后音量 | 波形、相关性、音量数值不能替代听感 |
| 发布材料 | 视频/封面/文案匹配；ZIP 完整且逐文件一致；用户选定版本正确 | 发布包存在不等于已上传或已发布 |

没有音频感知能力时不要以转写或播放器已打开当作完整试听，记录“自动音轨检查已做，主观全片试听未完成”。不能为了报告漂亮而隐藏实际限制。依然完成能完成的画面和文件检查，交付可审阅成片。

硬问题先修复：文件损坏、轨道缺失、错字漏字、改变说话含义、字幕/口型漂移、挡脸、意外黑边、动效导出失效、声量异常、包里装错版本。审美与节奏另按实际体验判断，不用技术通过与用户争辩。

对新的全片执行完整检查；之后的定点修正验证受影响部分及全片文件完整性。封面改字不需要重新编码未变视频；只移动已通过检查的成片则用哈希确认完整性，不为了“验证”再压一遍。

## 轻量记录

在现有制作说明中维护下列信息即可，不制造一堆独立验收表：

```text
本期主题 / 原片与选定人像 / 本次授权范围
当前交付文件 / 用户状态：待看、已选定或被否定
剪辑与速度 / 字幕规则 / 重点动效及对应时间
已完成的自动检查 / 实际看过或听过的范围 / 未完成项
依赖与复现入口 / 若有清理：废纸篓位置和恢复映射
```

建议留下一个精简的成片关键画面检查图和一份检查记录，不长期堆逐帧 PNG、失败渲染日志或多个同内容报告。

## 可恢复整理

本用户已有持续授权：完成文件制作或选定替代版本后，自动整理本任务确认无用的产物；不再要求用户重复说“其他清掉”。

1. **判定当前。** 看实际选择，不按修改时间选最大版本。选定后保留当前交付、一套可编辑工程和必要依赖、用户原始素材、独特必需输入、精简检查证据。仍在比较的候选保留；用户明确要留备份时遵从。
2. **检查引用。** 查工程、素材表、打包/导出脚本及软链接；旧文件夹里有当前依赖就先把必需文件迁到当前工程并修复引用，不能连同整个旧目录扔掉。
3. **限定目标。** 只处理能证明由本任务生成且已废弃的旧导出、旧源副本、过期 ZIP、样片工程、临时挑帧和冗余日志。不要动其他项目、用户原件、凭据、配置、版本控制、共享缓存、可复用 skill 或运行所需依赖。
4. **可恢复移动。** 移入系统废纸篓里唯一命名的任务子目录，保留相对路径；不永久删除、不清空废纸篓。没有可用废纸篓或实际权限时保留文件并如实说明整理未完成，不能静默改为永久删除。
5. **修复交付。** 统一当前导出路径，修正导航和说明，替换过期发布包并校验 ZIP 内容与当前交付逐文件一致。保持一份整理记录，记录恢复位置，不为每次清理生成一套档案。
6. **复查。** 重新列出保留树，确认原始素材与未修改媒体哈希不变，当前工程引用可用，打包正确。已有成功清理证据就核对后收尾，不重复搬文件或虚构清理动作。

最终回复简要给可用成片/发布包，说明有意义的变化与实际做过的检查。发生清理时交代保留什么、移走什么、可恢复位置；不声称聊天附件和外部已发布副本也被抹掉。
