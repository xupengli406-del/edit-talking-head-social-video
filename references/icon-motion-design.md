# 真实资料与可见的语义动效

用户反馈“太平、没网感”时，先看实际导出中图形的尺寸、动作距离、状态变化与完成态。换一个库只能提高造型一致性，不能替代构图和编排。不要把“放了图标”当成动效完成。

## 找库与选择

优先查看项目官方仓库、可用样例和 LICENSE。按本期语气挑一个主库，不因星数或“顶级”标签作选择：

- [Phosphor](https://github.com/phosphor-icons/core)：多字重和双色 SVG，适合生活、科技、人物互动等较亲和的叙述。双色部分可统一成一个强调色。
- [Lucide](https://github.com/lucide-icons/lucide)：统一线性图标，适合操作过程和工具说明。
- [Iconoir](https://github.com/iconoir-icons/iconoir)：较轻的几何线性表达，适合空间足够、画面清爽的片段；小屏粗细需实际检验。
- [lucide-animated](https://github.com/pqoqubbw/icons)：可参考对象局部运动。使用具体组件前查对应许可和使用限制；不要把网页 hover、循环或运行时回调直接搬进离线渲染。

把实际使用的 SVG 存入工程，记录仓库、固定提交/版本、文件名和许可证。只下载所需集合，保留授权文本；主库不要在同片里随意混成不同笔画、透视和填色。图标是示意，不是产品照片、真实产品结构或官方界面。

## 从名词变成关系

先写一句视觉动作，再选图标。例如：

| 口播含义 | 图标扮演的角色 | 可见变化与完成态 |
| --- | --- | --- |
| 远程看家 | 手机、家庭 | 两端先出现，线路接通，信号到达；连接态停留 |
| 跟随拍摄 | 拍摄者、相机 | 人先走，相机延迟跟上，最终保持距离 |
| 定制外壳 | 主体、画笔/外壳 | 外壳被选中、替换或从主体分离；修改对象清楚 |
| 未来做家务 | 灯、水杯、洗衣设备 | 随对应发声依次切换任务；持续保留“未来设想”范围提示 |
| 价格反差 | 预订、预期、公布价 | 预期与实际金额有明确替换/揭晓；最终金额稳定可读 |

不要给每个名词贴一个同时弹跳的图标。一个主要关系通常用一至三个对象表达；更多对象采用分步揭示。没有贴切图标时，用简单、有依据的自绘关系图，或保留真人表达。

## 构图、层级和运动

- 普通口播默认满屏，避免仅为放图标将真人缩小而留下大块黑边。真实证据值得成为重心时，可让截图居中盖脸，或让资料铺满主画面、真人进入小窗。本用户已明确认可资料盖脸和真人小窗，后续同类口播默认沿用，无需反复确认；其他用户按各自授权与偏好处理。小窗必须与资料区域互不遮挡，讲完自然回到满屏。不要反复突然放大人脸。
- 图标要在手机尺寸辨认得出。人脸移动时复查图形跨过头发、皮肤和浅色墙面的对比度；必要时仅给功能标签加局部承托，不依赖静态背景上的一次对比度通过。以1080宽竖屏为例，主图标可从100–160像素比较，辅助图标可更小；这是起点，不是固定规范。真实预览中仍像小装饰就重新分配面积，不堆数量补救。
- 同一时刻只让一个主要关系发生变化。用位移、连接、局部旋转、替换或任务接力产生意义；外层统一淡入不能算对象自身动画。
- 形状、笔画、圆角和色彩成体系。强调色用于当前对象或结果；普通字幕保持稳定。无需把所有颜色、细节和动作都统一成一个机械模板。
- 按发声锚点进入，做一次明确动作，停稳供阅读，再退出。复杂动作分阶段，阶段间要能看懂结果。不要为了填满几秒重复抖动、呼吸、旋转。
- 数字不在随机金额间闪动；逐位揭示或滚动时检查遮罩，不能溢出半截数字。型号、金额、单位在完成态必须准确完整。
- 对近距离手持原片，动效优先落在图形和关系上。偶尔缩小真人腾出讲解空间可以，不要每个切口都做推拉或转场。

## 可复现与细查

使用当前视频框架的可定位时间线驱动动画。重复作用于同一对象的 fromTo 等动画要有确定初态，随机跳转、首帧和并行渲染应一致；不依赖鼠标、实时时钟或页面加载后才启动的循环。

较大返修先导出代表性短片，覆盖普通口播→重点图形→回到真人。确认尺寸、字幕、完整动作和退出都成立，再扩到全片。

最终检查实际编码文件：

1. 每个重点动作前、中、完成态和退出，确认入场看得见、无元素穿字、没有导出后静止。
2. 每个剪辑接缝的前后连续帧；区分说话找词、普通跳切、解码停帧与播放器缓冲。自动停帧/静音检测只报候选，不直接删掉所有停顿。
3. 检查真正卡住的语义：重复句首、重说词、同义绕回、接缝残留半个词。先修原声剪辑，再重新映射字幕和动效，不能靠大动画遮掉声音问题。
4. 开头、中段、结尾的音画映射和字幕锚点，防止变速后累计漂移。没有实际听觉能力时，不把转写、波形或无静音报告写成“完整试听通过”。
5. 用户反馈和实际视觉体验优先于工具通过。静帧对比证明构图，连续帧证明发生了变化；它们都不能单独证明1×播放节奏舒服。

## 完整口播默认执行的真实资料步骤

- 先读转写，在现有分镜或制作说明中列出需要支撑的原声锚点和事实，再主动查找对应材料。具体品牌、型号、价格、功能、新闻事件、软件操作都可触发；不是只有说出“真实”二字才找素材，也不需要用户逐张提供截图。
- 优先官网、官方发布会、原始公告或文档、真实产品或应用界面，以及用户提供的实测素材；官方无法取得时可用可追溯的可靠报道，并标明实际来源。核对型号、版本、日期与该句结论；图片只能支持它实际展示的事实。品牌标识用于明确对象，不单独当作功能或价格证据。
- 介绍对象时展示真实外观及适量官方标识，报价时展示价格原页或发布会画面，讲功能时展示对应资料或真实操作界面。纯观点和抽象概念不强行配“证据”，可用满屏真人或语义图形。图标用于解释关系，不能代替产品长相或事实证据。
- 在现有时间线或分镜记录原声锚点、图源、支撑的事实、展示方式、停留和退出。每个相关重点都做素材适配判断，不固定每隔几秒插图，不照搬上一期的图片数量、品牌、颜色或价格布局。
- 保留原始素材、页面链接和素材哈希；画面简短标注图源。转引媒体的发布会图标明媒体图源，宣传场景与本人实测分开，不生成假的发布会截图。
- 横版发布会图应完整呈现关键型号、价格和原水印；为竖屏重新安排标题、资料图、说明与真人小窗，不用空黑边凑画幅。长图局部可在原生裁切窗口展示，保留整张输入和裁切位置。
- 一次资料揭示包含明确入场、稳定阅读、退出；先做含普通口播和资料小窗的短片，检查实际编码完成态、进入与回退，尤其核对小窗脸部是否被资料层遮住。

## 三种画面状态如何选择

| 表达任务 | 默认画面状态 | 必须保住的效果 |
| --- | --- | --- |
| 个人态度、铺垫、转折和连续讲述 | 真人满屏，按需直接叠加短图形 | 人物自然，没有为放图标挤出的大块黑边 |
| 需要观众看清一张真实图、型号、报价或细节 | 资料居中出现，可盖住脸成为重心 | 图片与原声相关，关键内容和水印完整，字幕可读，停稳后退出 |
| 需要持续阅读或解释真实资料 | 资料成为主画面，真人等比缩入辅助小窗 | 主画面有明确内容层级；小窗脸部完整且不被资料或字幕盖住；结束恢复满屏 |

在三种状态间按讲述穿插，不把整条视频做成常驻小窗或连续幻灯片。品牌标识按需出现，不机械全片悬挂。复用的是选材、构图和验收原则，每条片子仍需根据素材重新设计和审看，不能承诺调用 Skill 就自动达到完全相同的观感。
